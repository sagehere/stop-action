# 备份、迁移与回退

## 备份协议

完整备份v3默认密码加密，在浏览器原生Web Crypto完成：PBKDF2-SHA-256，600000次，随机16字节盐；AES-256-GCM，随机12字节IV，固定协议additionalData。参考[MDN deriveKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey)。密码至少12字符，密码/密钥不保存，关闭对话框后清空输入。丢失密码无法恢复。

可主动选择明文完整备份、CSV摘要；模板导出不包含Session或Coach对话。完整备份包含模板、实例、任务、历史、修订、设置、参数确认记录和当前训练检查点。令牌不导出；恢复外部Coach配置后重新授权。界面只记录「已生成/已发起下载」，无法验证操作系统是否保存文件。

导入顺序：读取/解密→格式与结构校验→兼容处理→合并或替换预览→确认→sessions/kv单事务提交。最大50MB。密码错误、篡改、未知版本、结构无效、事务异常不更改已有数据。合并相同ID相同内容跳过；冲突保留本机，并展示冲突ID。合并不覆盖本机设置/当前主计划，新增实例以暂停状态导入。替换会覆盖现有数据，当前训练恢复为暂停，关闭期间不算有效时长。

兼容ec-training-backup v1/v2/v3和受支持旧Session字段。旧记录不补算不可靠的暂停时长；clockVersion缺失视为旧版1，默认趋势使用新版2，可以显式筛选旧版。不同方案配置、阶段、提示模式、阈值、计时口径分组；前后各不足3条只作描述。

## 原数据迁移

旧localStorage在IndexedDB写入全部成功并标记后才清理。重复迁移以原ID幂等写入；失败保留localStorage和错误信息。升级受阻/多标签页给出提示。

旧计划保存原元数据 `legacyPlanBeforeMigration`，迁移为「旧版进行中计划」，保留原阶段/训练ID/现有安排及Session快照；只生成缺失未来安排，绝不冒充新8周内置模板。`migration-long-v1`成功提交后防止重复迁移。新空安装不制造旧计划。

## 发布与回退

1. 升级前导出并实际核对旧版明文备份或离线保存的完整备份；保留旧镜像tag及digest，不仅依赖latest。
2. 在独立浏览器配置/隔离测试域名验证升级与导入；新版本生成加密完整备份，确认可解密预览。
3. 回退服务器到保留的旧镜像摘要；客户端使用独立浏览器配置恢复升级前备份。回退镜像本身不会回退IndexedDB或清除Service Worker。
4. 必须在没有进行中训练时处理客户端缓存/数据；先保留新备份，再清除该站点缓存和数据，并打开旧版本恢复旧备份。不要无备份清空站点。
5. 如需把升级后Session带回旧版本，使用新版本主动明文导出或在离线隔离环境解密，再用旧版导入器恢复。原旧版导入器接受ec-training-backup的sessions，但不支持加密外壳和长期模板/实例；长期结构必须保留在v3原文件，回到v2应用后再恢复。

`tests/rollback.cjs <旧提交> [Playwright模块路径] [浏览器channel]`对真实旧版本HTML/app.js/db.js做隔离浏览器恢复测试，核对升级前备份和升级后记录；没有发布新镜像或替用户清空真实浏览器数据。容器级拉取/回退需要部署环境，验收状态见RELEASE_VALIDATION.md。
